# الأدوار والصلاحيات

المصدر: `set-roles` (قراءة فقط؛ "+ دور جديد" يعيد 404 فلم تُقرأ صفحة إضافة دور). أسماء المستخدمين وعناوينهم **لم تُنسخ**.

## الأدوار المرصودة
| الدور | الوصف الوظيفي | مصفوفته معروضة؟ |
|---|---|---|
| مدير النظام | كل الصلاحيات بما فيها الإعدادات [مُستنتج] | لا |
| محاسب | الفواتير والقيود والدليل بقيود (أدناه) | **نعم** |
| مندوب مبيعات | إنشاء فواتير لعملائه [مُستنتج] | لا |
في الديمو مستخدمان: أحدهما "مدير النظام" والآخر "محاسب". دور واحد لكل مستخدم (عمود "الدور" مفرد) [مُستنتج].

## مصفوفة دور "محاسب" (مرئي)
| الشاشة/الكيان | عرض | إضافة | تعديل | حذف | اعتماد | طباعة | تصدير |
|---|---|---|---|---|---|---|---|
| فواتير المبيعات | ✓ | ✓ | ✓ **(مسودة فقط)** | ✗ | ✗ | ✓ | غير معروض |
| القيود اليومية | ✓ | ✓ | ✓ | ✗ | ✗ | ✓ | غير معروض |
| دليل الحسابات | ✓ | ✗ | ✗ | ✗ | — (لا ينطبق) | ✓ | غير معروض |
| الإعدادات | ✗ | ✗ | ✗ | ✗ | — | ✗ | غير معروض |
أعمدة المرجع: عرض، إضافة، تعديل، حذف، اعتماد، طباعة (لا عمود "ترحيل" مستقل؛ "اعتماد" للفاتورة يقابل "ترحيل" للقيد [مُستنتج]).
الشاشات غير المدرجة في المصفوفة (العملاء، الموردون، الأصناف، المشتريات، السندات، التقارير، الضرائب): صلاحياتها غير معروضة — Q-61.

### تناقض ظاهري يحتاج حسماً
"محاسب" لا يملك "اعتماد" فواتير المبيعات، لكن سجل النشاط يعرض "اعتماد" فاتورة بواسطة المستخدم ذي دور "محاسب" — هل "حفظ وإصدار"
لا يُعدّ "اعتماداً" في الصلاحيات، أم أن الصلاحيات لا تُفرض؟ → Q-65 (عالية). **للمنفّذ:** "حفظ وإصدار" = اعتماد، ويتطلب صلاحية `approve`.

## الصلاحيات الخاصة (مرئي، لدور محاسب)
| الصلاحية | محاسب | الأثر |
|---|---|---|
| رؤية التكلفة | ✗ | إخفاء أعمدة التكلفة (قائمة الأصناف، قيد التكلفة؟) [مُستنتج] |
| تعديل سعر البيع | ✓ | تعديل السعر في سطر الفاتورة |
| تجاوز حد الائتمان | ✗ | منع إصدار فاتورة تتجاوز حد العميل [مُستنتج] |

## نطاق الصلاحية (الكل / الخاص به)
غير ظاهر في المرجع. دور "مندوب مبيعات" يوحي بنطاق "الخاص به" (فواتيره/عملاؤه) [مُستنتج] ⇒ نموذج البيانات يحوي `created_by` على
المستندات و`salesman_id` على الفاتورة، والعمود `role_permission.scope` (all/own) — انظر `03-data-model.md`. Q-61.

## الفصل بين الصلاحيات الدقيقة
| الإجراء | مستقل في المرجع؟ | المصدر |
|---|---|---|
| حفظ المسودة | ضمن "إضافة" | مرئي |
| الإصدار/الاعتماد | مستقل ("اعتماد") | مرئي |
| التعديل قبل الإصدار | "تعديل (مسودة فقط)" | مرئي |
| التعديل بعد الإصدار | غير مسموح لمحاسب؛ لغيره غير معروف | مرئي جزئياً |
| الحذف | مستقل | مرئي |
| تغيير التاريخ | غير موجود كصلاحية | — |
| تغيير السعر | مستقل (صلاحية خاصة) | مرئي |

## الفترات المقفلة
الإقفال صلب لكل المستندات ("الفترة المقفلة تمنع ترحيل أي مستند بتاريخ داخلها"). من يقفل/يعيد الفتح: من يملك صلاحية "الإعدادات"
[مُستنتج] (محاسب لا يملكها). لا استثناءات أدوار ظاهرة. Q-60.

## ربط مجموعات الصلاحيات بالوحدات
صفحة "إضافة دور" غير متاحة (404) ⇒ الربط `مجموعة الصلاحيات ← الوحدة` غير متحقق. المقترح: صفوف المصفوفة = شاشات الوحدات المفعّلة،
وتختفي صفوف الوحدات المعطّلة [مُستنتج].

## حدود الاعتماد والقيود على الفروع/المستودعات/مراكز التكلفة
غير موجود في النظام المرجعي.

## سجل التدقيق
- **ما يُسجَّل (مرئي):** الوقت (دقيقة)، المستخدم، الإجراء، رقم السجل — المرصود إجراء "اعتماد" فقط.
- **ما لا يُعرض:** القيم قبل/بعد، عنوان IP، فلاتر. **للمنفّذ:** سجّل الإنشاء والتعديل (قبل/بعد) والحذف والاعتماد والترحيل والإقفال لكل كيان مالي.
- **أين يُعرض:** المزيد… > سجل التدقيق (`audit-log`).
