# التقارير

المصادر: شاشات `rpt-*` (معاينة على الشاشة فقط؛ لا تنزيل). المعادلات بدلالة `03-data-model.md`.
التقارير الموثّقة: 9 (4 مالية + 4 تشغيلية + منشئ مخصص)؛ التدفقات النقدية **جزئي** (توقف عند انتهاء الجلسة + CAPTCHA).

## RPT-01: ميزان المراجعة
- **الشاشة:** `rpt-trial-balance` · **الغرض:** أرصدة كل الحسابات افتتاحية + حركة + ختامية لفترة.
- **المعايير والفلاتر:**
  | الفلتر | النوع | إلزامي | افتراضي | ملاحظات |
  |---|---|---|---|---|
  | من / إلى | تاريخ | نعم | بداية السنة المالية / نهاية الفترة | |
  | المستوى | قائمة (1، 2، 4 تفصيلي) | نعم | 4 | المستوى 3 غير معروض في الخيارات |
  | تضمين القيود غير المرحّلة | منطقي | لا | لا | |
  | إخفاء الأرصدة الصفرية | منطقي | لا | نعم | |
  | الفرع | قائمة (الكل/فرع) | لا | الكل | بُعد تحليلي |
  | العملة | قائمة | لا | الأساسية | الخيار الوحيد المرئي |
- **الأعمدة:**
  | العمود | المعادلة |
  |---|---|
  | افتتاحي مدين/دائن | `Σ(jl.debit_base − jl.credit_base)` حيث `je.entry_date < من`، يُعرض في جهة المدين إن كان موجباً وإلا الدائن |
  | حركة مدين | `Σ jl.debit_base` حيث `من ≤ je.entry_date ≤ إلى` |
  | حركة دائن | `Σ jl.credit_base` بالشرط نفسه |
  | ختامي مدين/دائن | الافتتاحي + الحركة مدين − الحركة دائن، في جهته |
  الشرط العام: `je.status='posted'` (أو `IN ('posted','draft')` عند تفعيل غير المرحّل)، `jl.branch_id = الفرع` إن حُدد.
- **التجميع والمستويات:** الحساب التجميعي = Σ أبنائه حتى المستوى المختار؛ إخفاء الصفري اختياري.
- **الإجماليات:** Σ كل عمود؛ **Σ مدين = Σ دائن** لكل زوج أعمدة.
- **المقارنات:** لا يوجد.
- **التصدير والطباعة:** Excel (POST)، طباعة (رابط يعيد 404).
- **التفاعل:** النقر على الحساب ← كشف الحساب (نص مرئي) ← المستند.
- **تناقض:** أرقام المرجع لا تُشتق من قيوده (AN-01، AN-03) — المعادلة أعلاه هي الصحيحة.
- **اختبار للمنفّذ:** 3 مستندات معروفة ⇒ كل رصيد = Σ أسطر قيوده، وΣ المدين = Σ الدائن، وفلتر الفرع يقسم الحركة بلا فقد (Σ الفروع = الكل).

## RPT-02: قائمة الدخل
- **الشاشة:** `rpt-income-statement` · **الفلاتر:** الفترة (قائمة فترات — ربع سنوي مرصود)، مقارنة بالفترة السابقة (منطقي).
- **البنود:**
  | البند | المعادلة |
  |---|---|
  | إيراد المبيعات | `Σ(jl.credit_base − jl.debit_base)` لحسابات `type='income'` |
  | تكلفة المبيعات | `Σ(jl.debit_base − jl.credit_base)` لحسابات دور `sales_cost` (و`purchases` [مُستنتج]) — تُعرض بين قوسين |
  | مجمل الربح | الإيراد − التكلفة |
  | المصروفات التشغيلية | `Σ(debit_base − credit_base)` لبقية حسابات `type='expense'` (ومنها فروق العملة [مُستنتج]) |
  | صافي الربح | مجمل الربح − المصروفات التشغيلية |
- **التصنيف:** من نوع/دور الحساب [مُستنتج] — لا إعداد تقارير ظاهر. **لا فلتر فرع** (Q-49). المقارنة: عمود الفترة السابقة + [مُستنتج] نسبة التغير.
- **اختبار:** صافي الربح = التغير في حقوق الملكية غير المقفل في المركز المالي (المركز المالي **غير موجود في النظام المرجعي** ضمن القائمة — Q-62).

## RPT-03: أعمار الديون
- **الشاشة:** `rpt-ar-aging` · **الفلاتر:** كما في (تاريخ)، حسب (تاريخ الاستحقاق/تاريخ الفاتورة)، الفرع.
- **الأعمدة:** العميل · غير مستحق · 1–30 · 31–60 · 61–90 · أكثر من 90 · الإجمالي (+ عمود "دفعات غير مخصصة" مذكور نصاً).
- **المعادلة:** لكل فاتورة `status='issued'` و`invoice_date ≤ كما في`: `المتبقي = total_base − Σ allocations حتى التاريخ`؛ `الأيام = كما في − due_date` (أو `invoice_date`)؛ ≤ 0 ⇒ غير مستحق؛ وإلا الشريحة. الشرائح قابلة للتعديل (نص مرئي).
- **اختبار اتساق:** Σ إجمالي الأعمار = رصيد دور `clients` (Σ الحسابات الفرعية) في التاريخ نفسه — يفشل في المرجع (AN-01/02).
- **سؤال:** عملة الأعمار للعميل الأجنبي (Q-50).

## RPT-04: التدفقات النقدية — جزئي
- **الشاشة:** `rpt-cash-flow` · **غير متحقق:** الطلب أعاد صفحة "انتهت صلاحية الجلسة" + CAPTCHA ⇒ توقف (Q-16).
- **المقترح [مُستنتج]:** طريقة مباشرة من أسطر قيود حسابات `treasury`/`bank` مصنّفة حسب الحساب المقابل (تشغيلي: عملاء/موردون/ضريبة/مصروفات؛ استثماري: أصول؛ تمويلي: حقوق ملكية/قروض)، مع فلتر الفترة والفرع.

## RPT-05..08: تقارير العمليات (المبيعات، المشتريات، المدفوعات، حركة المخزون)
- **الشاشات:** `rpt-sales`، `rpt-purchases`، `rpt-payments`، `rpt-stock` — بنية واحدة.
- **المعايير:** من/إلى · `group_by` ∈ {day, week, month, client, staff} · `view` ∈ {summary, details}.
- **الأعمدة (summary):** الفترة/المجموعة · العدد · الإجمالي.
  | التقرير | العدد | الإجمالي |
  |---|---|---|
  | المبيعات | `count(sales_invoice)` حيث `status='issued'` | `Σ total_base` (أو الصافي — Q-48) |
  | المشتريات | `count(purchase_invoice)` | `Σ total_base` |
  | المدفوعات | `count(receipt)` | `Σ amount × exchange_rate` |
  | حركة المخزون | `count(stock_movement)` | `Σ total_cost` (+ الكمية [مُستنتج]) |
- **details:** سطر لكل مستند/حركة ضمن المجموعة [مُستنتج — المعاينة لم تُظهر فرقاً، Q-48].
- **ملاحظة:** `client`/`staff` تُعرض لكل التقارير حتى حيث لا معنى لها (المشتريات ← المورد؛ المخزون ← المستودع/الصنف) — المقترح: أبعاد خاصة بكل تقرير (Q-19).
- **مركز التقارير:** 40 رابطاً = 4 × 5 × 2 — في النظام الجديد شاشة واحدة لكل تقرير بمحدّدات.

## RPT-09: منشئ التقارير المخصص
- **الشاشة:** `rpt-builder` · المصدر (الفواتير/القيود) ثم الأعمدة والتجميع والفلاتر وحفظ التقرير (نص مرئي). يُخزَّن في `saved_report.definition` (jsonb). تفاصيل الخطوات غير متحققة (Q-51).

## تقارير متوقعة غير موجودة في النظام المرجعي (ضمن النطاق)
المركز المالي، كشف الحساب العام (موجود فقط عبر النقر من الميزان)، إقرار ضريبة القيمة المضافة، تقييم المخزون في تاريخ، أعمار الموردين، تقرير فروق العملة — كلها **غير موجودة في القائمة أو المركز** (Q-62). يقترح البناء: المركز المالي وإقرار الضريبة وتقييم المخزون في المرحلة D.

## تحقق الاتساق (للمنفّذ)
- ميزان المراجعة: Σ المدين = Σ الدائن = Σ أسطر القيود المرحّلة.
- صافي الربح في قائمة الدخل = الفرق المرحّل إلى حقوق الملكية في المركز المالي.
- رصيد العميل في كشف الحساب = إجمالي أعماره = رصيد حسابه الفرعي.
- قيمة المخزون (Σ طبقات FIFO) = رصيد دور `stores` لكل فرع وللشركة.
