# Build Brief — نظام محاسبي مكافئ وظيفياً (متعدد الفروع ومتعدد العملات)

> **إلى الوكيل المنفّذ:** هذا الملف هو تعليماتك الرئيسية. ابنِ نظاماً يطابق **سلوك** النظام الموصوف في هذا المجلد،
> بهوية وتصميم جديدين كلياً. حين يتعارض هذا الملف مع ملف شاشة، فملف الشاشة أدق في التفاصيل، وهذا الملف أعلى في
> الأولويات والنطاق. ما يحمل وسم [مُستنتج] افتراض معقول وليس حقيقة مؤكدة؛ ما في `09-open-questions.md` لم يُحسم.
> **تنبيه:** الدراسة جرت في **وضع القراءة فقط** — منطق الترحيل في `04b-posting-matrix.md` مبني على قيد مرئي واحد
> وعلى الإعدادات والمبادئ، لا على اختبارات مُنشأة. ابنِ المحرك قابلاً للإعداد بحيث يُصحَّح أي سطر ببيانات لا بكود.

## 1. الهوية والملكية الفكرية (إلزامي)
- صمّم هوية بصرية جديدة: اسم المنتج، الشعار، لوحة الألوان، الخطوط، الأيقونات، الرسوم — كلها من اختيارك/من فريقنا.
- لا تستخدم اسم النظام المرجعي أو أي أصل منه، ولا تبحث عنه على الإنترنت لتقليد شكله.
- لا تنسخ نصوص المساعدة أو التسويق. التسميات الوظيفية للحقول (مثل "مركز التكلفة") مصطلحات محاسبية عامة ويمكن استخدامها.
- الواجهة تُبنى من الصفر وفق `07-ux-guidelines.md` (أنماط تفاعل لا أشكال).

## 2. السياق
- **الدولة:** المملكة العربية السعودية — ضريبة القيمة المضافة 15% بفئات S/Z/E/O وأسباب الإعفاء `VATEX-SA-…`، والفوترة الإلكترونية **ZATCA المرحلة الثانية** (Clearance للضريبية، Reporting للمبسطة خلال 24 ساعة)، وحدة EGS لكل فرع.
- **اللغة والاتجاه:** العربية RTL افتراضياً + الإنجليزية LTR، حقول ثنائية الاسم.
- **تعدد الفروع:** فرعان مرجعيان (الرياض رئيسي، جدة)، الفرع **بُعد تحليلي** على كل سطر قيد، ترقيم مستقل لكل فرع وسنة، مستودع لكل فرع، حساب جاري لكل فرع للتحويلات بينهما، تقييد المستخدم بفروعه.
- **تعدد العملات:** عملة أساسية (SAR، مقفلة بعد أول قيد) + عملات بسعر يدوي (6 خانات)، عملة لكل عميل/مورد، فروق عملة محققة وإعادة تقييم غير محققة بعكس تلقائي.
- **تعدد الشركات:** حساب واحد بعدة شركات (مبدّل شركات) ⇒ `company_id` + عزل صفوف.
- **الحجم:** 15 وحدة (14 تطبيقاً: 7 مفعّلة و7 معطّلة + الإعدادات)، 52 شاشة (45 كاملة، 6 جزئية، 1 متخطّاة)، 49 جدولاً، 9 تقارير، 4 أدوار (انظر `00-executive-summary.md`).
- **المستخدمون والأدوار:** `05-roles-permissions.md`.

## 3. التقنية والهيكل
- **التقنية:** تُركت للوكيل المنفّذ. **اقتراح مبرَّر:** TypeScript كاملاً — Next.js (App Router) للواجهة (دعم RTL وi18n جيد) + NestJS للخادم + PostgreSQL 16 (RLS، `numeric`، triggers مؤجّلة يعتمد عليها `03-schema.sql`) + Prisma أو Drizzle للهجرات، وطابور مهام (BullMQ/pg-boss) لإرسال ZATCA وإعادة المحاولة وعكس إعادة التقييم والقيود المتكررة. أي بديل مكافئ مقبول بشرط: decimal حقيقي، معاملات ACID، وطابور موثوق.
- **مبادئ معمارية:**
  - طبقة "دفتر الأستاذ" (ledger) مستقلة: كل الوحدات تنشئ قيوداً عبر خدمة واحدة `PostingService` تفرض التوازن (بالعملة الأساسية **وبعملة المعاملة**) والفترة المفتوحة والتسلسل والفرع؛ لا كتابة مباشرة في `journal_line` من أي وحدة أخرى.
  - **محرك ترحيل قابل للإعداد:** `PostingService` يقرأ قواعد `04b-posting-matrix.md` كبيانات (جدول
    `posting_rule(operation, conditions, line_no, debit_role, credit_role, amount_expr)` + جدول `account_routing(role|operation, account_id)` + تجاوزات بطاقة الصنف/العميل)،
    لا `if/else` مكتوبة في الكود لكل مستند. تغيير حساب أو قاعدة = تعديل بيانات لا نشر كود. أولوية حل الحساب: بطاقة الصنف/الطرف ← التوجيه ← خطأ صريح (لا حساب افتراضي صامت).
  - **كل سطر قيد بعملتين:** `debit/credit` بعملة المعاملة + `debit_base/credit_base` + `exchange_rate`؛ كل التقارير المجمّعة بالعملة الأساسية.
  - المبالغ `decimal` لا `float` في كل الطبقات (DB/API/الواجهة)؛ الـ API يعيد المبالغ نصاً عشرياً غير منسّق مع رمز العملة.
  - تعدد الشركات: `company_id` في كل جدول + Row Level Security؛ تعدد الفروع: `branch_id` على المستندات والأسطر + فلترة بفروع المستخدم.
  - المستندات المُصدَرة غير قابلة للتعديل ولا الحذف؛ التصحيح بمستند عكسي (إشعار دائن/مدين).
  - **كل تغيير حالة عبر POST/PATCH/DELETE مع CSRF** — لا روابط GET تغيّر الحالة (AN-07).
  - سجل تدقيق لكل تغيير على الكيانات المالية (قبل/بعد).
- **الهيكل المقترح:**
  ```
  apps/web            واجهة (RTL-first، i18n ar/en)
  apps/api            الخادم (REST + OpenAPI)
  apps/worker         مهام الخلفية: ZATCA، عكس إعادة التقييم، القيود المتكررة
  packages/ledger     محرك الترحيل والقيود والفترات والعملات (+ اختباراته، ومنها T-PM المولّد من 04b)
  packages/inventory  حركات المخزون وطبقات FIFO لكل مستودع والتحويلات
  packages/tax        محرك الضريبة + ZATCA (UBL، التجزئة، التوقيع، QR)
  packages/db         المخطط والهجرات (ابدأ من 03-schema.sql)
  ```

| T-04 | ضريبة غير شاملة + تقريب | سطر 3 × 33.33 بنسبة 15% | صافي 99.99، ضريبة 15.00، إجمالي 114.99 (تقريب لكل سطر بخانتين — Q-01) |
| T-05 | ضريبة شاملة | سعر شامل 115.00 بنسبة 15% | صافي 100.00، ضريبة 15.00 |
| T-06 | صفرية/معفاة | سطر بفئة Z أو E | ضريبة 0.00، سبب الإعفاء (VATEX) إلزامي، الفئة محفوظة على السطر |
| T-07 | ميزان المراجعة | فاتورة معتمدة صافي 1,000.00 + مسودة 2,000.00 + قيد يدوي 500.00 | الإيراد 1,000.00 فقط؛ Σ مدين = Σ دائن؛ مع "غير المرحّل": يُضاف صافي المسودة 2,000.00 (لا الإجمالي) |
| T-08 | فاتورة بيع مخزنية | 2 × 100.00، تكلفة FIFO 60.00 للوحدة، 15% | قيد 1: مدين العميل 230.00 / دائن sales 200.00 / دائن vat_output 30.00؛ قيد 2: مدين sales_cost 120.00 / دائن stores 120.00 |
| T-08b | خدمة وبند حر | خدمة 1 × 150.00؛ بند حر "تركيب" 1 × 100.00 | قيد إيراد وضريبة فقط؛ لا قيد تكلفة؛ البند الحر بلا وصف مرفوض |
| T-08c | خصم الإجمالي | سطران 600.00 و400.00، خصم إجمالي 100.00، 15% | صافي 900.00 (موزّع 540/360)، ضريبة 135.00، إجمالي 1,035.00 (Q-17) |
| T-09 | فروق العملة المحققة | فاتورة 1,000.00 USD بسعر 3.75 (3,750.00 SAR)، تحصيل كامل بسعر 3.76 | مدين البنك 3,760.00 / دائن العميل 3,750.00 / دائن fx_realized 10.00؛ الفاتورة مدفوعة |
| T-09b | فرق عملة مع دفع جزئي | الفاتورة نفسها، تحصيل 400.00 USD بسعر 3.74 | مدين البنك 1,496.00 / مدين fx_realized 4.00 / دائن العميل 1,500.00؛ المتبقي 600.00 USD بسعر 3.75 |
| T-09c | الرقابة بالعملة الأساسية (AN-01) | فاتورة 1,000.00 USD بسعر 3.75 + فاتورة 1,000.00 SAR | رصيد `clients` = 4,750.00 SAR؛ اللوحة "مستحقات العملاء" = 4,750.00 |
| T-10 | FIFO | مستودع واحد: وارد 10 @ 5.00 ثم 10 @ 7.00، بيع 15 | التكلفة 85.00؛ المتبقي 5 @ 7.00 = 35.00 |
| T-10b | إعادة تقييم وعكس | رصيد عميل 2,000.00 USD سعر دفتري 3.74، تقييم في 31 مارس بسعر 3.75 | قيد 31 مارس: مدين العميل 20.00 / دائن fx_unrealized 20.00؛ قيد 1 أبريل عكسي تلقائي؛ إعادة التشغيل لنفس التاريخ مرفوضة |
| T-10c | FIFO لكل مستودع | الرياض: 10 @ 5.00؛ جدة: 10 @ 6.00؛ بيع 4 من جدة | التكلفة 24.00 (طبقات جدة فقط) وبُعد الفرع = جدة |
| T-11 | تحويل بين فرعين | تحويل 5 وحدات تكلفة 5.00 من الرياض إلى جدة | إرسال: مدين جاري جدة 25.00 / دائن stores 25.00 (بُعد الرياض)؛ استلام: مدين stores 25.00 / دائن جاري الرياض 25.00 (بُعد جدة)؛ Σ جاري الفروع = 0؛ قيمة المخزون الإجمالية ثابتة؛ طبقة جديدة في جدة @ 5.00 |
| T-11b | تحويل داخل الفرع | تحويل بين مستودعين في الفرع نفسه | لا قيد؛ الطبقات تنتقل بتكلفتها |
| T-11c | رصيد افتتاحي | صنف 10 @ 50.00 | مدين stores 500.00 / دائن opening_balance 500.00؛ طبقة 10 @ 50.00 |
| T-12 | ZATCA مبسطة | فاتورة لعميل فرد في فرع مربوط | QR (TLV/Base64) بحقوله، UUID، ICV متزايد، PIH = تجزئة الفاتورة السابقة للوحدة، إبلاغ خلال 24 ساعة مع إعادة محاولة |
| T-13 | ترقيم لكل فرع وسنة | فاتورتان في الرياض وفاتورة في جدة سنة 2026، ثم فاتورة في الرياض 2027 | `RYD-INV-2026-00001`، `RYD-INV-2026-00002`، `JED-INV-2026-00001`، `RYD-INV-2027-00001`؛ المسودات لا تستهلك أرقاماً |
| T-14 | ZATCA قياسية | فاتورة لمنشأة برقم ضريبي وعنوان وطني | Clearance قبل المشاركة؛ رفض الإصدار إن نقص الرقم الضريبي أو العنوان الوطني للمشتري |
| T-15 | إشعار دائن | إشعار دائن لفاتورة T-08 بسبب إلزامي | P-31/32: عكس الإيراد والضريبة والتكلفة، رصيد العميل يعود، مرجع الفاتورة الأصلية في XML (381) |
| T-16 | الصلاحيات والاعتماد (AN-09) | محاسب بلا صلاحية اعتماد + فاتورة 10,000.00؛ ثم بالصلاحية؛ ثم فاتورة 60,000.00 | رفض 403؛ قبول؛ مرحلتان (مدير فرع ثم مدير مالي) |
| T-17 | تقييد الفروع | مستخدم مسموح له جدة فقط | لا يرى مستندات الرياض في القوائم والتقارير والـ API، ولا يُنشئ فيها |

## 6. البيانات الأولية (Seed)
- دليل حسابات افتراضي بأربعة مستويات وحساب لكل دور في معجم `04b` (بما فيها: ضريبة المدخلات، فروق العملة المحققة وغير المحققة، جاري الفروع لكل فرع، فروقات الجرد، أرصدة افتتاحية، أرباح محتجزة).
- ضرائب السعودية: قياسية 15% (S)، صفرية (Z) وأسبابها، معفاة (E) وأسبابها، خارج النطاق (O).
- العملة الأساسية SAR + USD وEUR معطّلة افتراضياً؛ قواعد الترقيم في `04-business-rules.md` §13 (+ المشتريات والتحويلات — Q-54).
- أدوار افتراضية: مدير النظام، محاسب، مندوب مبيعات، مدير فرع، مدير مالي.
- **بيانات تجريبية وهمية فقط** (عميل-001، مورد-001، صنف-001…)، لا بيانات من النظام المرجعي.

## 8. خارج النطاق
- **وحدات معطّلة غير مدروسة:** الرواتب، الحضور والانصراف، الأصول الثابتة، نقاط البيع، المشاريع وتتبّع الوقت، العقود والإيجارات، المتجر الإلكتروني (`01-modules.md`).
- **شاشات جزئية** (تُبنى بافتراضات موسومة): نماذج سعر الصرف والفرع والضريبة والدور (روابطها 404)، معاينة طباعة الفاتورة (404)، التدفقات النقدية (انتهاء جلسة + CAPTCHA) — راجع `10-coverage-report.md`.
- **مبدّل الشركات:** الوظيفة مطلوبة (تعدد الشركات)، لكن الشركة الأخرى لم تُفتح.

## 9. تعريف "انتهى"
- كل معايير القبول لكل مرحلة محققة، والاختبارات الإلزامية (ومنها T-PM لكل سطر وT-AN لكل تناقض) تمر في CI.
- `03-schema.sql` (أو ما يقابله من هجرات) يُطبَّق على PostgreSQL نظيف بلا أخطاء.
- لا أثر لاسم أو أصول النظام المرجعي في الكود أو الواجهة أو الوثائق.
- وثائق تشغيل (README) وهجرات قاعدة بيانات قابلة للتكرار، وOpenAPI للـ API.
