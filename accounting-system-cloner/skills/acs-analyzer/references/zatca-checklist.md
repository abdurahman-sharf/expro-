# قائمة فحص الفوترة الإلكترونية السعودية (ZATCA / فاتورة)

الغرض: معرفة **ما يطبّقه النظام المرجعي** من متطلبات هيئة الزكاة والضريبة والجمارك، ليُنقل للمنفّذ كمتطلب.
المتطلبات التنظيمية تتحدّث؛ ما يلي خلاصة عامة للتوجيه، وعلى المنفّذ الرجوع إلى أحدث المواصفات الرسمية
المنشورة على بوابة الهيئة (اللائحة، ومواصفات XML التفصيلية، ودليل المطوّرين، وواجهات Fatoora) قبل التطبيق.
اكتب هذا التنبيه في `08-build-brief.md` أيضاً.

**كله قراءة:** لا تضغط "إرسال إلى الهيئة"، "ربط الجهاز/Onboarding"، "توليد CSID"، "إعادة الإرسال". هذه عمليات
لا تُعكس وقد تُفسد تسلسل الفواتير لدى الهيئة.

## 1. المرحلة الأولى (الإصدار)
- [ ] الفواتير تُصدر إلكترونياً من النظام (لا يدوية/Word).
- [ ] **رمز QR** على الفاتورة المبسطة (وعادة على الضريبية أيضاً): هل يظهر في معاينة الطباعة؟
  محتوى المرحلة الأولى بترميز TLV ثم Base64: (1) اسم البائع، (2) الرقم الضريبي للبائع، (3) الطابع الزمني،
  (4) إجمالي الفاتورة مع الضريبة، (5) إجمالي الضريبة.
- [ ] الحقول الإلزامية الظاهرة: "فاتورة ضريبية" / "فاتورة ضريبية مبسطة"، رقم تسلسلي فريد، تاريخ ووقت الإصدار،
  الرقم الضريبي للبائع، وللمشتري في الضريبية، تفاصيل السطر والضريبة لكل نسبة، الإجمالي بالريال.
- [ ] منع التعديل/الحذف بعد الإصدار (تعديل بإشعار دائن/مدين فقط).
- [ ] اللغة العربية على الفاتورة (ثنائية اللغة مسموحة).

## 2. المرحلة الثانية (الربط والتكامل)
- [ ] **صيغة XML وفق UBL 2.1** بالمواصفة السعودية: هل يوجد زر "عرض/تنزيل XML" لفاتورة؟ (المعاينة مسموحة؛ إن
  احتوت بيانات حقيقية فلا تنزّلها — وثّق وجود الميزة فقط.)
- [ ] **الختم التشفيري** (توقيع ECDSA) و**تجزئة الفاتورة** (SHA-256) و**تجزئة الفاتورة السابقة (PIH)** لسلسلة
  غير قابلة للكسر، و**عدّاد الفواتير (ICV)**، و**UUID** لكل فاتورة.
- [ ] **QR المرحلة الثانية**: يضيف إلى الحقول الخمسة: (6) تجزئة XML، (7) التوقيع، (8) المفتاح العام، (9) توقيع
  شهادة الختم (للمبسطة).
- [ ] **الربط بالهيئة (Onboarding):** شاشة لإدخال رمز OTP من بوابة فاتورة لتوليد CSID (امتثال ثم إنتاج)، لكل
  وحدة/جهاز/فرع. وثّق: هل الربط لكل فرع؟ لكل نقطة بيع؟ ما الحقول المطلوبة (اسم الوحدة، الرقم التسلسلي للجهاز،
  نوع الفواتير المصرّح بها: ضريبية/مبسطة/كلاهما)؟ **لا تنفّذ الربط.**
- [ ] **الاعتماد (Clearance)** للفاتورة الضريبية B2B: تُرسل للهيئة وتُعتمد قبل تسليمها للمشتري. هل يعرض النظام
  حالة "معتمدة من الهيئة / مرفوضة / تحذيرات"؟
- [ ] **الإبلاغ (Reporting)** للفاتورة المبسطة B2C: تُصدر للعميل ثم تُبلَّغ خلال 24 ساعة. حالة "تم الإبلاغ"؟
  طابور إعادة المحاولة عند انقطاع الاتصال؟
- [ ] عرض رسائل التحقق من الهيئة (أخطاء/تحذيرات) على المستند.
- [ ] PDF/A-3 مع XML مضمّن (اختياري لدى بعض الأنظمة).

## 3. أنواع المستندات ورموزها
| المستند | رمز النوع | ملاحظات |
|---|---|---|
| فاتورة ضريبية (قياسية) | 388 + نوع فرعي `01…` | B2B/B2G، Clearance |
| فاتورة ضريبية مبسطة | 388 + نوع فرعي `02…` | B2C، Reporting |
| إشعار دائن | 381 | **يجب** أن يرجع للفاتورة الأصلية + سبب الإصدار |
| إشعار مدين | 383 | **يجب** أن يرجع للفاتورة الأصلية + سبب الإصدار |

- [ ] هل يفرّق النظام تلقائياً بين القياسية والمبسطة (بحسب وجود رقم ضريبي للمشتري؟ بحسب نوع العميل؟ يدوياً؟).
- [ ] الحالات الخاصة في النوع الفرعي: فاتورة نيابة عن الغير، فاتورة اسمية، تصدير، فاتورة ملخصة، فوترة ذاتية — أيها مدعوم؟
- [ ] الإشعار الدائن/المدين: حقل الفاتورة الأصلية إلزامي؟ حقل السبب إلزامي؟ قائمة أسباب ثابتة أم نص حر؟

## 4. فئات الضريبة وأسباب الإعفاء
- [ ] الفئات: S (أساسية 15%)، Z (صفرية)، E (معفاة)، O (خارج النطاق).
- [ ] رموز أسباب الإعفاء/الصفر (سلسلة `VATEX-SA-…`) ونصها: قائمة منسدلة في تعريف الضريبة أو السطر؟ إلزامية مع Z/E/O؟
- [ ] السطر الواحد بفئة واحدة؛ ملخص الضريبة مجمّع حسب الفئة والنسبة.

## 5. بيانات البائع والمشتري
- [ ] الرقم الضريبي (15 رقماً، يبدأ وينتهي بـ 3) — تحقق الطول والنمط في الحقل؟ (`maxlength`/`pattern` مرئي.)
- [ ] السجل التجاري أو معرّفات أخرى للبائع/المشتري (CRN، MOM، MLS، 700...) — نوع المعرّف قائمة ثابتة؟
- [ ] **العنوان الوطني**: رقم المبنى (4 أرقام)، الشارع، الحي، المدينة، الرمز البريدي (5 أرقام)، الرقم الإضافي —
  حقول منفصلة في بطاقة العميل والشركة؟ إلزامية للمشتري في الفاتورة القياسية؟

## 6. المبالغ والعملة
- [ ] الفاتورة بعملة أجنبية: هل يُعرض إجمالي الضريبة بالريال السعودي أيضاً (متطلب)؟
- [ ] الخصم على مستوى المستند (Allowance) وعلى مستوى السطر — كلاهما مدعوم؟
- [ ] الدفعات المقدمة وتسويتها في الفاتورة النهائية.
- [ ] التقريب: المواصفة تتسامح بفروق تقريب صغيرة محددة؛ وثّق ما يفعله النظام.

## 7. نقاط البيع والوضع غير المتصل
- [ ] هل تصدر نقاط البيع فواتير مبسطة دون اتصال وتُبلَّغ لاحقاً؟ كيف يُعرض الطابور؟

## 8. الحفظ والأرشفة
- [ ] أرشفة XML والفواتير المعتمدة (المدة وفق اللوائح السارية — يتحقق منها المنفّذ).
- [ ] منع حذف الفواتير المبلّغة/المعتمدة على مستوى قاعدة البيانات.
