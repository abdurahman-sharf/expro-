# acs-explorer — رسم خريطة النظام

مهمتك أن تعرف **كل** ما في النظام قبل دراسة أي شيء بعمق. الخريطة هي مقام التغطية: أي شاشة لا تدخلها
الخريطة لن تُدرس ولن يبنيها المنفّذ. لذلك العمق هنا أقل أهمية من الشمول.

## القواعد الإلزامية (مختصر — المرجع الكامل: `references/guardrails.md`)

- **التفويض:** لا تبدأ إلا إن كان `progress.md` يسجّل تأكيد التفويض (أو أكده المستخدم صراحة الآن). وإلا توقف واسأل.
- **الدخول:** لا تكتب اسم مستخدم أو كلمة مرور أو رمز تحقق في أي حقل أبداً. إن لم تكن داخل النظام، افتح صفحة
  الدخول واطلب من المستخدم الدخول بنفسه وانتظر تأكيده. لا تحفظ بيانات دخول أو كوكيز أو رموز جلسة.
- **الديمو أولاً:** إن وُجدت شركة ديمو فاعمل عليها.
- **قراءة فقط:** التنقل وفتح القوائم والتبويبات مسموح. لا تضغط أي زر إجراء (حفظ، ترحيل، حذف، إرسال، استيراد،
  مزامنة، معالجة...). في الاستكشاف لا حاجة حتى لفتح نماذج "جديد" إلا لمعرفة إن كانت معالج خطوات.
- **الخصوصية:** لا تنسخ أسماء أو مبالغ أو أرقاماً حقيقية من القوائم. لا تتنقل إلى شركات أو مستأجرين آخرين.
- **حدود الاستنساخ:** وثّق الأسماء الوظيفية للشاشات والتخطيط العام بالكلمات فقط؛ لا شعار ولا ألوان ولا أيقونات
  ولا لقطات قوالب. سمِّ النظام "النظام المرجعي" في المخرجات.

## متى تتوقف وتسأل

انتهاء الجلسة أو إعادة التوجيه للدخول · CAPTCHA · عنصر قائمة غير واضح الأثر (مثل "مزامنة الآن" داخل القائمة
نفسها — بعض القوائم تنفّذ عند النقر) · مبدّل شركات يعرض شركات أخرى أو لوحة إدارة للمزوّد · قسم خارج النطاق
المتفق عليه · أي طلب يتجاوز القراءة.

## الطريقة

### 1. القائمة الرئيسية
- اقرأ الصفحة كاملة (`read_page` / `get_page_text`)، لا ما يظهر فقط: القوائم الجانبية كثيراً ما تكون مطوية.
- افتح كل عنصر رئيسي لتكشف قوائمه الفرعية. سجّل لكل عنصر: الاسم، المسار في القائمة، الرابط الناتج.

### 2. الأماكن المخفية (الأكثر نسياناً)
افحصها صراحة وسجّل أنك فحصتها حتى لو كانت فارغة:
- أزرار "المزيد" / "…" / "عرض الكل" في القوائم والشرائط.
- القوائم المنسدلة في الشريط العلوي، وزر "+ جديد" السريع (يكشف أنواع المستندات).
- قائمة المستخدم (الملف الشخصي، الشركة، الاشتراك، التفضيلات).
- الإعدادات بكل تبويباتها الفرعية (غالباً عشرات الشاشات: الترقيم، الضرائب، القوالب، الصلاحيات، التكاملات).
- التبويبات **داخل** الشاشات (عميل ← فواتيره، دفعاته، كشف حسابه) — كل تبويب له وظيفة مستقلة = شاشة فرعية.
- الإجراءات الجماعية في القوائم، وقوائم "إجراءات" داخل السجلات (تكشف شاشات مثل "تحويل إلى فاتورة").
- لوحة المعلومات وأدواتها، ومركز التقارير (كثيراً ما يحوي عشرات التقارير في صفحة واحدة: كل تقرير شاشة).
- شاشات تظهر فقط من رابط داخل شاشة أخرى (تفاصيل سجل، معاينة طباعة). استنتج نمط رابطها من رابط سجل واحد.

### 3. أنماط الروابط
- استبدل المعرّفات والقيم بمتغيرات: `/invoices/8841/edit` ← `/invoices/{id}/edit`؛ `?branch=3` ← `?branch={branchId}`.
- إن كان النظام SPA بروابط hash (`#/sales/...`) فوثّقها كما هي.
- راقب طلبات GET في الشبكة (اختياري) لتأكيد أسماء الكيانات، دون تسجيل قيم أو ترويسات.

### 4. التصنيف
لكل شاشة نوع واحد: `list` (قائمة سجلات) · `form` (نموذج إدخال) · `detail` (تفاصيل سجل) · `report` ·
`settings` · `dashboard` · `wizard` (معالج خطوات). إن جمعت الشاشة قائمة ونموذجاً جانبياً فسجّلهما شاشتين
أو اذكر ذلك في `notes`.

### 5. الأولويات
| الأولوية | ماذا | لماذا أولاً |
|---|---|---|
| 1 | البيانات الأساسية: دليل الحسابات، العملاء، الموردين، الأصناف، الضرائب، العملات، مراكز التكلفة، الفروع، المستودعات | كل المستندات تعتمد عليها؛ فهمها يجعل تحليل المستندات أسرع |
| 2 | المستندات: قيود، فواتير بيع/شراء، سندات، مرتجعات، حركات مخزون | تحمل القواعد المحاسبية |
| 3 | التقارير | معادلاتها تتحقق من فهمنا للقيود |
| 4 | الإعدادات والصلاحيات | تكمّل الصورة |
رتّب الوحدات بحقل `priority` على مستوى الوحدة أيضاً.

## المخرجات

1. **`01-sitemap.json`** وفق المخطط في `references/output-structure.md`. بعد الكتابة:
   ```bash
   python3 <skill-dir>/scripts/acs_tool.py validate --project <spec-dir>
   ```
   أصلح أي خطأ حتى يمر. كل الشاشات تبدأ `status: "pending"`، وما هو خارج النطاق `skipped` مع `skip_reason: "خارج النطاق"`.
2. **`01-sitemap.md`** للقراءة البشرية:
   ```markdown
   # خريطة النظام المرجعي
   ## ملخص
   الوحدات: N · الشاشات: M · حسب النوع: list x، form y، ...
   ## الأماكن المفحوصة
   - [x] القائمة الرئيسية  - [x] "المزيد"  - [x] قائمة المستخدم  - [x] الإعدادات (12 تبويباً) - [ ] ...
   ## الشجرة
   ### 1. المحاسبة العامة (أولوية 1)
   - **البيانات الأساسية**
     - دليل الحسابات — `list` — `/accounting/accounts` — `gl-coa`
   ## التخطيط العام (وصف وظيفي)
   مثلاً: قائمة جانبية قابلة للطي + شريط علوي فيه بحث عام وزر "جديد" سريع + منطقة محتوى بجداول.
   ## ترتيب الدراسة المقترح
   ```
3. **الشاشات المكتشفة لاحقاً:** إن طلب منك acs-analyzer إضافة شاشة، أضفها في موضعها الصحيح وشغّل `validate`.
4. سجّل: `acs_tool.py log "اكتملت الخريطة: N وحدة، M شاشة"` واعرض على المستخدم الملخص وترتيب الدراسة،
   واسأله إن كان هناك قسم يعرفه ولم يظهر (مثلاً لأنه يحتاج صلاحية أعلى أو اشتراكاً).
