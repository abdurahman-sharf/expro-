# TAX2 — تصميم المرحلة T4: الشحن والعملة الأجنبية والدفعات المقدمة ووحدة القياس

| البند | القيمة |
|---|---|
| التاريخ | 2026-11-21 |
| الموافقة | «أوافق على T4 ثم واصل بعد ذلك العمل حتى تنتهي من الخطة بشكل كامل» |
| المرجع | بطاقة T4 في الخطة، وR-04 §9.2 و§9.4 و§9.5 (نسخة محلية) |
| المبدأ | كل تغيير محصور في **بيع اللقطة** (T3) وفي الوضع السعودي. خارجه لا يتغير شيء |

## 1. الشحن: رسم على مستوى المستند (BG-21)

| البند | القرار |
|---|---|
| النوع | الشحن في بيع اللقطة **رسم على مستوى المستند** (`cac:AllowanceCharge` و`ChargeIndicator=true`، رمز السبب `FC`)، بفئة S ونسبة ضريبة الشحن في الإعدادات |
| الفئة | يُضم صافي الشحن إلى خاضع فئته (R-04 §9.2: BT-116 = صافي الأسطر + الرسوم − الخصومات)، وتُقرَّب ضريبة الفئة **مرة واحدة** على المجموع (BR-CO-17) |
| الصافي | غير شامل: `round2(الشحن)`. شامل: `round2(الشحن − ضريبته)` |
| اللقطة | `sales_vat_totals.charges` (عمود جديد): ما ضُم من رسوم إلى خاضع الفئة. تُكتب بعد تثبيت الرسوم في معاملة البيع |
| الشحن بلا ضريبة | **يُرفض عند الإتمام في الوضع السعودي** (الشحن خدمة خاضعة) |
| القيد | الضريبة = ضريبة الفئات (تشمل الشحن)، والإيراد = خاضع الأسطر، والشحن = صافيه، والفرق سطر التقريب (T3) |
| المستند | الرسم، و`ChargeTotalAmount`، و`TaxExclusiveAmount` = الأسطر + الرسوم |
| التقرير الضريبي | يقرأ اللقطة وحدها، فلا يُضاف الشحن مرتين |
| التسوية | تبقى مرفوضة في الوضع (D-07، T3). الرسم الموجب يُدخل صنفًا مصنفًا |

## 2. العملة الأجنبية

| البند | القرار |
|---|---|
| المستند | `DocumentCurrencyCode` = عملة البيع، و`TaxCurrencyCode` = SAR. **TaxTotal الأول بالريال** (BT-111 = ضريبة المستند × سعر الصرف مقرّبة)، والثاني بعملة المستند مع الفئات |
| السعر | سعر صرف البيع المحفوظ (`sales.currency_rate`) |
| تحقق القيد | يقارن بمبالغ القيد بعملة المستند (`accounting_journal_lines` يحمل العملة) |

## 3. الدفعة المقدمة (R-04 §9.5)

| البند | القرار |
|---|---|
| الدفعة في الوضع | تحمل ضريبة عند الاستلام: المبلغ شامل بنسبة فئة S السارية، فقيدها: من الخزينة الإجمالي، إلى العميل الخاضع، وإلى ضريبة المخرجات الضريبة. ولقطتها في جدول جديد |
| مستندها | فاتورة دفعة مقدمة (`InvoiceTypeCode` 386) بسطر واحد |
| استعمالها | حين تُستعمل في فاتورة، يُرحَّل قيد يعكس ضريبة الجزء المستعمل (من ضريبة المخرجات إلى العميل)، فيتطابق حساب العميل مع ذممه |
| الفاتورة النهائية | سطر تعديل لكل دفعة مستعملة: كمية 0، وضريبة السطر 0، ومرجعها (KSA-26 و28 و29 و30=386)، وفئتها ونسبتها، وخاضعها وضريبتها (KSA-31 و32)، و`PrepaidAmount` = مجموعها، والمستحق = الإجمالي − المدفوع مقدمًا + التقريب |
| الدفعات قبل التفعيل | **لا تتغير** (D-11): تبقى رصيدًا بلا ضريبة |

## 4. وحدة القياس

رمز UN/ECE اختياري لوحدة القالب (عمود جديد)، يُكتب في `unitCode` لسطر البيع إن وُجد، وإلا `PCE` كما اليوم.

## 5. الاختبارات

ملف لكل صنف: `VatCalculatorTest` (ضم الرسم)، و`SaleAmountsTest` غير موجود فتُضاف حالات الترحيل في `SalePostingBuilderTest`، و`EInvoiceBuilderTest`، و`UblInvoiceXmlTest`، و`TaxDocumentsTest`، و`SalePostingTest` (الرفض)، و`CustomerAdvancesTest`، وترحيلات الأعمدة والجداول.
