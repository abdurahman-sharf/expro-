# تحويل «الاول برو» إلى نظام محاسبي متكامل

الهدف: إضافة طبقة محاسبة كاملة (دليل حسابات، قيود، دفتر أستاذ، فترات، قوائم مالية، ذمم وخزائن) فوق نظام نقاط البيع الحالي، بتفكيك نظام محاسبي مرجعي وفهم ما ينقص OSPOS.

- **الحالة:** تحليل وتصميم مكتمل للمراجعة. لم يبدأ التنفيذ، وينتظر القرارات السبعة في [خارطة الطريق](04-roadmap.md).

| الوثيقة | المحتوى |
|---|---|
| [01 — تفكيك النظام المرجعي](01-daftra-reference.md) | وحداته، نواته المحاسبية (الدليل، القيد، التوجيه، الفترات)، تقاريره، وما لم أتحقق منه |
| [02 — تدقيق الوضع الحالي](02-ospos-audit.md) | ما في OSPOS، ومصفوفة 18 فجوة، و10 مخاطر موجودة في الشيفرة تؤثر على التصميم |
| [03 — التصميم المعماري](03-architecture.md) | الجداول، خدمة الدفتر، قواعد الترحيل، الدليل الافتراضي، الفترات، التقارير، الصلاحيات، الاختبار |
| [04 — خارطة الطريق](04-roadmap.md) | المراحل A–F وبوابات قبولها، والمخاطر، والقرارات المطلوبة |

أهم النتائج في سطور:

1. OSPOS **لا يحوي أي محاسبة قيد مزدوج**: لا دليل ولا قيود ولا أستاذ. التقارير تُحسب من جداول العمليات.
2. نبني **دفتر أستاذ يُغذّيه البيع والاستلام والمصروف داخل معاملتهم الحالية**، فلا بيع بلا قيد، ولا إعادة كتابة للتشغيل. والميزة **مطفأة افتراضيًا** فلا يتأثر أحد قبل التفعيل.
3. ثلاث مشاكل في الشيفرة تحكم التصميم: **نوع الدفع نص مترجم**، و**الاستلام بلا دفعات ولا ضرائب** (فلا ذمم موردين ولا ضريبة مدخلات)، و**البيع يُعدَّل بعد الحفظ** فيلزم عكس وإعادة ترحيل.
